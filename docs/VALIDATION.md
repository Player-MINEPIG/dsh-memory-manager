# Compatibility verification

[中文](VALIDATION_zh-CN.md)

Use temporary profiles and synthetic resource bodies. Keep durable DSH history authoritative and integrate through public plugin services; installation must not patch DSH core. Tavern requires assembler; memory-manager is optional. Keep exact revisions, package hashes and run-specific results in private acceptance records.

## Automated checks

Clone manager and assembler into sibling directories, run `npm ci`, then `npm run check`. For current Tavern integration set `DSH_MEMORY_RUNTIME` to the runtime directory, and `DSH_MEMORY_TAVERN` plus `DSH_MEMORY_MVU` to the Tavern checkout, then run `npm test`.

Real Host request tests need public request-assembly protocol 1. A stock runtime without this capability cannot establish request injection acceptance; record the gap. Synthetic providers avoid online model requests. Optional separate MVU-dependency fixtures supplement, rather than replace, current Tavern tests.

Check exact request contributions and durable evidence, MVU updates, source CAS/grants, scoped cold reads, cancellation, reload and provider removal. Native card writes use Tavern bindings/grants/schema; Manager rules govern model reads and assistant updates.

## Optional extension lifecycle

In an authorized isolated profile, hash durable session files (including compressed journals), assembler strategies and Manager configuration. Install all three plugins; deny a synthetic world-book read through Manager and verify it is skipped. Remove Manager with `dsh plugin --profile web remove dsh-memory-manager`, restart, and verify native world-book defaults and MVU updates resume. The generic Manager source must withdraw from assembler. Reinstall and confirm retained rules resume without rewriting source content or losing DSH history. Use unused fixtures for writes, not user policies.

## Browser acceptance

Check native global Settings and session memory tabs, detail configuration/options, cold scope switches, explicit retry and cancellation on navigation. Loading, unavailable session and absent source are distinct states. Cover desktop and narrow layouts.

Check preset create/edit, editable adapter defaults, export/reimport, and atomic rejection of malformed fields or unsupported adapter capabilities. Failed imports must leave the file, revision and every candidate item unchanged. File-picker or browser-tool limits must be recorded separately from server validation.

Do not send online requests without authorization. Automated tests do not establish browser/desktop acceptance; record exact remaining manual checks with the private installation receipt.

# Memory Manager adapter protocol 1

The trusted Host service is `dshMemoryManager`, `protocolVersion: 1`. Adapters own content, revision, persistence and execution. The manager owns declarative management configuration and a bounded observation journal. It does not evaluate untrusted code, create task tools, or copy external authority ledgers. The independent assembler owns the optional request adapter. The manager exposes its read-only resource snapshot and trigger contract. See [assembler integration](ASSEMBLER_en.md) for requestAssemblyResources and lifecycle ownership.

`registerAdapter(adapter)` returns an unload disposer. An adapter has `id`, `name`, `authority`, and async `list({scope,signal})`, `read({id,scope,signal})`. Records are `{id,type,content,revision,name?,authority?,scope?}`; IDs must be globally stable (use a provider prefix), and the same ID always names the same entity. `read` returns null for missing content. Optional `update({id,content,expectedRevision,operationId,scope,signal})` and `copy({id,newId,scope,signal})` delegate editing and copying to the authority. Copy must generate/require a new ID; never reinterpret scope as a new instance of an existing ID. Optional `setManagementMode({id,mode,expectedRevision,operationId,scope,signal})` explicitly transfers ownership through the source. Optional `validateConfig(config)` validates source-specific type/on/rule/strategy names; optional `observe(listener)` reports facts and returns a disposer. Source APIs must enforce their own authorization, CAS and idempotency. Optional `optionCatalog.presets` declares reusable defaults; optional async `validatePreset(configuration)` performs additional resource-independent validation and must throw on rejection without accessing resource content or executing rules. See [presets](PRESETS_en.md) for the strict portable format, library methods and atomic save semantics.

Scope is Host-bound JSON `{sessionId?,branchId?,authority?,taskId?,runId?,attemptId?}`. Scope is not content identity. Real Agent scope keys are NOT serialized. An adapter requiring an Agent must resolve the actual Agent in its trusted closure; remote execution must never fall back to a local ledger. A management UI request is not a model tool grant.

Scope-directory context only enriches the bound session: a directory may omit sessionId when returning workspace/entity facts, but cannot delete, replace or invent that lookup anchor. If it returns sessionId it must equal the input session. Non-source callers' workspace/character/preset/persona claims are discarded before resolution; trusted-source facts and overlapping directory facts must agree or fail with SCOPE_CONTEXT_CONFLICT. Null optional facts mean absence. Scope leases accept only synchronous true and are rechecked by the usage/source final commit boundary; a changed directory generation or fact cannot revive an old permit.

`getConfig(id)` returns `{config,origins,revision}`. Effective config fields are `id,type,whitelist,blacklist,store:{on,rule,strategy},retrieve:{on,rule,strategy},preset`. Empty whitelist matches nowhere; blacklist wins. Presets continuously override explicitly supplied fields except id/content/preset; rule trees, lists and operation chains replace as units. Config files contain only JSON. Adapter callers decide how to execute valid on/rule/strategy settings; the manager never creates a parallel memory engine. Explicitly native sources retain native behavior. For already managed sources, missing configuration or an empty whitelist prohibits managed execution and must not fall back to native behavior. Ownership is persisted by the source, separately from applicability.

`recordTrace({adapterId,id,eventId,phase,sessionId?,turn?,turnKind?,requestId?,revision?,detail?})` records adapter facts. `phase`: started, triggered, applied, skipped, failed, completed. Started remains active until a matching request/event completion/failure; history is separate from final request application. `turnKind`: human, task, system, unknown. Sources must not label dsh-task injections as human turns. Query filtering does not rerun retrieval. `query({scope?,turn?,turnKind?,status?,adapterId?,filters?})` accepts either a scalar or an array for each filter. Values within one dimension are OR; dimensions are AND; empty arrays mean unrestricted. HTTP query filters use repeated parameters (`adapterId=a&adapterId=b`), so commas remain literal ID characters. The response includes records, facts, config, diagnostics, `scope`, `facets.turns` and `catalogs` (per queried adapter, count before filters; null on failure). Optional adapter `describeScope(scope)` supplies a read-only scope explanation; it must not expand discovery or permissions. Turn facets are scoped but independent of selected turn/kind/status values. Global UI exposes resource-provider and configuration-field filtering; session controls remount and reset on scope changes. The table summarizes effective configuration; session detail includes application facts, including rows without recorded triggers. The existing `never` status means no trigger fact was recorded in the selected scope, not proof that the source was unused. Preview is not an applied event.

Adapters may declare `catalogScope:'all-sessions'` for native resources whose default scope includes every session. Session queries use their existing `list({scope:{sessionId,authority?},signal?})`, retaining the native provider's Agent/preset/cwd visibility. No Tavern binding capability is required. `dsh.skills` declares this contract; the native default-scope path is selected from this declaration, not an ID or label. Such catalogs report `catalogScope:'all-sessions',binding:'default'`, and do not fabricate resource binding facts. This visibility declaration changes neither configuration nor execution: adapter disable, explicit whitelist/blacklist and behavior rules keep their existing effect.

Sources requiring actual session/card bindings use the optional metadata capability `listBound({scope:{sessionId,authority?},signal?}) -> {items,revision,checkCurrent}`. The existing `tavernMemorySources.listBound` aggregator is preferred for its persisted-session/current-selection/MVU-source checks and is called once per query; adapters can expose the same capability directly. Items carry real stable `id,adapterId,type,name?,revision?,managementMode?,binding:{sessionId,kind,...source binding facts}` and optional metadata, never content, variables or history. Snapshots are ephemeral Host-only values; their synchronous `checkCurrent` is checked after the final source await, together with manager registration, enable state and service identity. It is never serialized or saved. Requests forward only sessionId and the requested authority; browser character/preset/Persona claims cannot establish bindings. Metadata is bounded to 2,000 records and 1,000,000 JSON characters.

Session reads may use the source’s public `withSessionRead({sessionId,signal},callback)` lease. Cold persisted sessions are inspected and borrowed only for the query, configuration or content read; no Agent is activated and no history is appended. The panel shows loading while the read is pending. `SESSION_READER_NOT_READY` (503) means initialization is pending; `SESSION_NOT_FOUND` (404) means the persisted session does not exist; other read errors remain failures. A source returning an empty confirmed catalog is distinct from all of these.

Session counts, turn facets and rows contain native default-scope resources and confirmed current binding pairs. Current bound resources without manager rules remain visible. Other-card rules, global whitelists, old Trace observations and missing configuration placeholders do not establish a current binding. For sources requiring binding, missing/old/unavailable capability produces explicit diagnostics and `catalogs[].binding:'unconfirmed'`, with no global list/read fallback; confirmed empty sets have count 0. Global administration retains configured and historical missing-resource entries. Directory visibility and resource binding do not grant prompt-use, content access or cross-card authority. Embedded books and MVU instances follow the owning currently selected card; selected standalone, session opening, ST preset/Persona associated books and session-bound templates follow the source's actual binding semantics. This package creates no cross-card enablement and does not allocate MVU state during directory lookup.

Tavern/MVU adapters remain optional. No central `dshMemory` readState/transact database is provided. A provider unavailable after unload is visible through session diagnostics and through global configuration/history entries.

The web client registers `dsh-memory-manager` in the public DSH `conversation.view` roster, alongside Chat and optional Tavern Trace. The view receives its session identity from standard slot props; it reuses the existing table, detail, filter and option pages. Session tables classify observations by source-reported turn and show running/past/never status for that turn (`never` is displayed as 未记录触发; actual applied facts are displayed as 已应用; source-authored world-book policy skips show 策略跳过 and their recorded reason). Query rows expose independent JSON `activeFacts` from the manager's current scoped activity, so activity in another turn does not label an older turn as running. Unknown turn facts are separate; a session without observations does not receive a fabricated turn. Current resources and effective configuration are shown, not reconstructed historical content/configuration. Status filtering in this view applies to each turn's rows. The global settings page remains ungrouped with no turn controls. No duplicate header action or shell overlay fallback is registered. When the official shell hides view tabs/body for blank sessions, the plugin does not create a substitute entry. Tavern is not required to register or use the view; its adapters and Trace remain optional. Slot disposal and session changes stop polling and discard the old component scope.

## Usage execution

`registerCondition({id,test(event,params)})`, `registerOperation({id,run(context),readOnly})` return disposers. `trigger({id,event,mode,preview,signal})` evaluates a frozen effective policy, scope and rule, then a trusted operation chain. Events include stable `eventId`, `on`, trusted `scope`, and optional `turn`, `turnKind`, `requestId`. Operations receive `{id,value,event,config,params,preview,signal}`. Only trusted Host plugins may register code. JSON configuration never executes code. `memory.read_content` and `memory.to_text` are built-in projections; they do not independently inject anything.

Source writes must persist their own operationId/revision receipts. The bounded manager trace is not an idempotency database; operations must forward stable source-owned intent IDs. Failed or unknown source outcomes must be reconciled at the authority. Configuration revision changes do not authorize replaying old writes.

For `tavernMvu` protocol 1, the optional adapter in this package registers a usage decision handler. MVU performs its own ordered strategy once. `managementMode:'managed'|'native'` is source-owned and persisted. Managed resources with unavailable policy, policy errors, empty whitelist or a denied scope fail closed. Explicitly native resources keep their native behavior. `setManagementMode({id,mode,expectedRevision,operationId,scope})` is an optional CAS ownership transfer; removal of a plugin or policy is not such a transfer.

The assembler-owned `adapters/memory-manager` registers `memory-manager.resources` with request lifetime only. `requestAssemblyResources()` returns `{available,entries}` where each detached entry contains id, adapterId and configurationSnapshot. The configuration snapshot uses the same effective local/preset configuration as read-only retrieval; source-owned entries are excluded. The adapter mounts through `connectMemoryManager(ctx,registry)` and calls the public bound `trigger` method. No assembly adapter is mounted by this package. Users must select this source in Tavern's assembly preset themselves. Retrieval runs read-only, without durable trace mutation. `block.id` hashes entity, resource revision, config revision and strategy revision; diagnostics carry the tuple. A separate Host observer matches the durable `request/assembly` messages to `llm/stream` messages and source nodes before recording application. This proves entry into the DSH request at that observation point, not network delivery or model comprehension. MVU's own source is excluded to prevent duplicate provision.

Timed provision and active wake are distinct: trusted scheduler adapters may call the same trigger interface, but this package creates no timer or task-run engine. Waking an Agent requires a separately authorized host scheduler capability. TaskSystem integration is a compatibility boundary, not an implemented adapter.

Host HTTP routes require the public `connection.admit` fence and authentication. Mutations additionally require same-origin JSON requests. Adapter ownership is reserved before side effects; queued observer callbacks are tied to the exact registration lifetime. Effective adapter configuration is validated on registration, reload and before execution. Request resolution isolates unavailable resources into diagnostics while retaining valid sources; caller cancellation still aborts the whole resolution.

## Stable Skill identity and mutation reservations

Virtual Skill definitions may opt in through `metadata.dshResourceIdentity: {version:1,namespace,id}`. Namespace and id are nonempty trimmed strings, at most 256 characters, maintained by the authoritative provider across restarts and body revisions. Namespace ownership, distinct shadow identities and new IDs for copies are the provider's responsibility. Content is not part of identity. Files retain path-based IDs. Unannotated virtual Skills have `skill-view:` handles and `capabilities.bind:false`, with `SKILL_STABLE_ID_REQUIRED` diagnostics. Handles remain usable for reading the current scoped catalog view but are not persistent resources, cannot be configured for managed usage and are not reused across adapter recreation. The upstream public catalog does not expose a universal durable locator; this limitation is explicit rather than guessed.

Query rows keep the resource `revision` and expose policy `configRevision` separately. A failed source mutation does not create a confirmed owner. Temporary identity reservations protect concurrent operations. A provider rejection with `committed:false`, or a documented precommit validation/authorization/CAS rejection, releases only that operation's reservation; existing owners and sibling reservations remain. An ambiguous outcome retains an uncertain reservation and a visible `MUTATION_OUTCOME_UNKNOWN` diagnostic until the source is reconciled by an authoritative read. Providers must not label a postcommit failure as a precommit rejection. The manager does not substitute its reservation table for source-owned CAS or idempotency.

## MVU native card observations and model policies

With the current Tavern contract, `card_variable_update` is a source execution fact, not a Manager store/retrieve permission request. Native card operations use the source's saved execution switches, active binding, separate write grant, CAS, idempotency and schema validation. Missing, denying or unloaded Manager configuration cannot grant or block those operations. The Manager observes source `started/triggered/applied/completed/skipped/failed` receipts; native commits have `configRevision:null` and only changed values produce `applied`.

The MVU adapter offers `assistant_message_committed` store policies and `before_model_request` retrieve policies. It no longer offers the old native card timing, cause condition, fixed write strategy or default card interaction preset. Existing persisted definitions are retained for inspection, but importing or saving unsupported fields is rejected. Such definitions do not control native execution; use Tavern's source execution and write controls for that purpose.

Model/store/retrieve decisions retain the exact configuration, reload epoch, scope, registration and condition leases. Changed configuration or same-function condition re-registration cannot revive an old permit. Request application evidence also recognizes assembly owned by either Tavern or the independent assembler, and requires matching durable request messages and included source nodes.

## Configuration reload

`reload()` reads and validates the saved JSON configuration. Structurally identical documents (including the same revision, ignoring formatting and object-key order) return `{revision,unchanged:true}` and clear a previous load error. The active document object is retained. A changed document must have a strictly higher revision and pass source validation before replacing the active document; success returns `{revision,unchanged:false}`. Changed content at the same revision, lower revisions, parse errors and validation failures preserve the last valid document. This reload operation is not a resource refresh and never silently increments disk revisions; the separate configuration editor save operation below increments revisions explicitly. Every reload attempt advances the pending epoch, including no-ops; earlier MVU permission leases stay invalid after reload/error recovery. Resource update CAS is unchanged.

## Configuration editor and effective field filters

`configurationSnapshot({id,adapterId})` (GET `/configuration`) returns `local` (null when absent), effective `config`, `origins`, `presets`, `revision`, `configError`, and source availability. It does not read resource content. Default whitelist/blacklist/preset origins are `default`; explicitly supplied entry fields are `local`; preset overrides are `preset:<id>`. `preset` itself remains local. Missing child fields have no provenance; a parent behavior object does not provide an origin for an absent child.

`validateEntry({id,adapterId,entry,expectedRevision})` (POST `/validate-configuration`) returns `{valid,revision,local?,effective?,origins?,diagnostics}`. Each diagnostic has `level: error|unknown|info`, `code`, `field`, `message`. It validates the proposed complete local entry against the current document/presets and the source's pure `validateConfig`, then checks registered named conditions and operation IDs. The source validation contract must be read-only. No resource list/read/mutation, condition evaluation, operation execution, configuration epoch change or disk write occurs. MVU marks `strategyOwner:'source'` because its source validates and executes its own ordered strategies. Missing source/validator/registry capabilities block saving; event reachability, resource existence/content compatibility and authorization remain explicitly unknown until runtime.

`saveEntry` (POST `/save-configuration`) takes the same arguments and revalidates independently of prior dry-run results. The resource ID and authoritative source binding remain stable. A different entry adapter is an explicit rule route, recorded with sourceAdapterId, and must confirm that exact resource/source pair through validateResourceRoute; source-owned routes are rejected. This never migrates body content or changes source permissions. It serializes with reload, checks expected revision and structural disk equality, writes a unique same-directory temporary file (0600) and fsyncs it, then rechecks disk, ownership, adapter lifetime and capability registrations immediately before synchronous atomic rename. After incrementing the revision, it validates the exact final document again (including the 2,000,000-character compact JSON size bound) before opening a temporary file. It increments revision once and publishes the new active document only after rename; an unchanged entry is a no-op. It returns the new snapshot plus `unchanged` and `validation`. Failures preserve the current document/file; stale revision or external disk changes return HTTP 409. Validation errors include diagnostics. Saving advances the same pending epoch as reload, revoking old runtime leases; dry-run does not. The editor modifies only the requested local entry, preserving other entries and preset definitions. It neither grants resource authority nor changes management ownership. External noncooperating writers can still race an OS-level read/rename pair; this is single-Host revision coordination, not a cross-process transactional database.

These routes use the existing Host admission and same-origin JSON mutation headers. Form drafts are page-memory only. Resource content continues through the separate source read/update CAS routes.

`filters` is a field-keyed object, serialized as JSON in HTTP query parameter `filters`. Allowed keys: `id`, `type`, `preset`, `whitelist`, `blacklist`, `store.on`, `store.rule`, `store.strategy`, `retrieve.on`, `retrieve.rule`, `retrieve.strategy`. Each value is `{mode:'exact'|'contains',values:string[],missing?:boolean}`. Values OR within a field, fields AND across; an empty values list without `missing` is unrestricted. `missing` matches absent/null fields. Type may use labeled source metadata for an unconfigured resource; a trace-only placeholder with no type remains absent and matches the missing selector. A real source or explicit configuration type named `unknown` remains a literal type. No other configuration values are invented. `on` arrays expose individual event names. Complex rules/strategies/lists use canonical JSON text with sorted object keys and array order preserved; contains is case-sensitive literal matching, never execution. Boolean false and the string "false" remain distinct. `facets.fields` provides available values before configuration/status filtering.

### Declarative capability catalog

GET `/options` and `manager.optionCatalog({id,adapterId,sessionId})` expose version 1 descriptions and a scope-independent `catalogRevision`. GET `/options-documentation` serves a rendered HTML page built from bundled Markdown with escaped input, no scripts and a restrictive CSP under the same Host admission. `validateEntry`/`saveEntry` accept optional `expectedCatalogRevision`, independently from `expectedRevision`. Registrations, unload, ABA re-registration and descriptor changes invalidate catalog decisions. Typed parameters and applicability metadata are checked server-side; source-owned strategy validation remains with the source. See [OPTIONS.md](OPTIONS.md) for the canonical descriptor contract, installed management presets and local declarative extensions. UI drafts use separate searchable selection pages and typed controls; no JSON form is required for management configuration.

`tavernMemorySources` protocol 1 supplies actual source-owned worldbook/template adapters. The manager replaces its legacy worldbook bridge for this service lifetime and restores the read-only bridge when appropriate. Generic request resolution excludes every source-owned adapter, so the source emits its content once. For sources implementing the defaults/delegation contract below, the source reports effective ownership from manager registration lifecycle. Legacy sources retain their existing modes. Managed execution requires a current configuration/default/binding/capability lease and source authorization.

### Scope directories and adapter controls

GET `/adapters` exposes installed resource and scope directory adapters plus known missing capability installation documentation. POST `/adapter-enabled` takes `{id,enabled,kind:"resource"|"directory"}` and changes only the current manager runtime; it preserves local rules and source content. Disabled and unloaded capabilities reject new operations and invalidate pending leases. Restart restores installed defaults.

GET `/scope-directory?providerId=...&kind=...&query=...&limit=...&cursor=...` returns bounded metadata `{items:[{id,label,labelState?,workspaceId?,workspaceLabel?}],nextCursor?,range?}` after Host admission. DSH retains a bounded snapshot from public `sessionQuery.listSessions(signal)` header metadata, with zero I/O title cache projections and WorkspaceRegistry. Cold names are explicitly cached or unnamed. Workspace queries do not enumerate session headers. `refresh=1` requests a new snapshot. `range` reports retained record/byte limits, expiry, source and whether results are partial. `scopeDirectoryLimits` defaults to `{maxRecords:2000,maxBytes:1000000,timeoutMs:3000,ttlMs:15000}`. Signed cursors bind query/workspace/snapshot, with lifecycle invalidation and per-page metadata stat checks. It never reads persisted session bodies or activates an Agent. The upstream header API remains unpaged; manager limits retained data and wait time, not upstream enumeration/allocation. Deployments lacking both public cold services use an explicitly loaded-only range. Optional `tavernScopeCatalog` v1 supplies paginated characterId/ST presetId/Persona userId and Host-only current scope leases; old unpaged body catalogs are not used as fallback. Display names are not identities; source visibility does not grant prompt-use or content access.

## Source defaults and effective delegation

A source-owned adapter, or the public MVU service forwarded through its manager adapter, may provide a synchronous read-only getter:

```ts
getManagementDefaults({id, scope?}): null | {
  protocolVersion: 1;
  revision: string;
  configuration: {type?: string; store?: object; retrieve?: object};
  scopePolicy: 'source-bound';
  checkCurrent: () => boolean;
}
```

The getter returns no resource body, identity, preset reference, wildcard whitelist or card grant. A global snapshot describes defaults; a scoped snapshot must validate the actual source resource/session binding. Defaults/binding/lifecycle changes revoke its Host-only lease. Manager passes `{providerId:'dsh-memory-manager'}` as the second `registerUsage` argument; compatible sources use this trusted registration to determine effective `managementMode`, synchronously revoke delegation on disposal and use source defaults for subsequent new operations after removal. Mere callbacks/observers must not be mistaken for manager presence. Invalid manager configuration denies rather than falling back as if the manager were absent.

Manager lazily composes the default base, then local fields, then existing preset fields. Explicit empty local store/retrieve objects retain disabled-mode semantics. No resource-mode CAS or user configuration migration is performed. Missing whitelist inherits source-bound eligibility only in the registered source's decision path; an explicit local/preset whitelist (including `[]`) overrides that eligibility. Blacklists still deny. Source permissions, selection, schema, revisions and card grants constrain actual use regardless of local selectors. Generic usage does not acquire source-bound authorization. An alternate rule route does not inherit the original source default base. Missing/invalid source defaults are reported rather than inferred from option presets.

Query rows, configuration snapshots and validation reports include JSON `sourceDefault:{available,revision?,scopePolicy?,configuration?,reason?,message?}` and effective `scopePolicy:'source-bound'|'whitelist'`; source leases are never sent to the browser. Field origins use `source-default`, `local`, existing `preset:<id>`, or generic `default`. The public source's actual `managementMode` determines the displayed manager/source label. Config errors appear with that label and block managed decisions. `GET /configuration` accepts optional `sessionId` for the same binding context as query.

The restore button uses the existing form/removal helpers and validate/save endpoint. It drops this resource's known policy overrides, preset reference and alternate route, preserving opaque fields. Its preview shows the true resulting source defaults; no global preset definition is changed. Existing file revision/disk/CAS checks govern publication. Resource content and current registration/delegation remain unchanged. First plugin installation creates an absent empty local override file with exclusive creation; an existing malformed/unreadable file is preserved.
